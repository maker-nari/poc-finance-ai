# 🧭 PoC 워크숍 진행 기록

## 프로젝트 주제

**AI 월말 정산 도우미 POC 프로토타입**

이 문서는 월말 정산표 초안 작성 업무를 대상으로 진행한 PoC 워크숍의 단계별 산출물을 정리한 문서입니다.

워크숍은 다음 흐름으로 진행되었습니다.

- PRE: 문제 후보 탐색 및 업무 맥락 정의
- STEP 1: 성과 문제 확정
- STEP 2: 업무 흐름 분석 및 병목 도출
- STEP 3: AI 적용 적합성 판단 및 역할 분담
- STEP 4: PoC 설계 및 프로토타입 구상
- STEP 5: OKR 및 확산/중단 의사결정 기준 수립

# PRE. 문제 후보 탐색

## 문제 상황

중소기업 회계담당자가 월말 정산 자료를 작성하는 과정에서 세금계산서, 지출 증빙 자료, 카드 내역 등을 취합하고 분류하는 데 시간이 오래 걸리는 문제가 발생하고 있습니다.

## 업무명

월말 정산 자료 작성 업무

## 발생 상황

매달 월말마다 각 부서에서 제출한 증빙 자료를 확인하고, 이메일과 구글드라이브 등에 흩어진 자료를 찾아 정리해야 합니다.

자료 제출 방식이 부서마다 다르고, 누락된 증빙은 이메일로 개별 요청하고 있습니다.

## 현재 처리 방식

- 엑셀로 수작업 정리
- 누락된 자료는 이메일로 개별 요청
- 거래처별·비용 항목별 분류도 수작업으로 처리

## 문제 후보

1. 월말 정산 자료 취합에 시간이 과다 소요되어 마감이 지연됨
2. 증빙 자료 누락으로 인해 재요청 및 재작업이 반복됨
3. 거래처별·항목별 분류 작업에 시간이 많이 들어 전체 처리 속도가 저하됨
4. 자료가 여러 채널에 분산되어 탐색 시간이 증가함
5. 수작업 정리 과정에서 오류가 발생해 정산 정확도가 떨어짐

## 선택한 핵심 문제 후보

1. 월말 정산 자료 취합 지연으로 마감이 늦어짐
2. 거래처/항목 분류 작업으로 처리 속도 저하
3. 자료 분산으로 탐색 시간 증가

## PRE 단계 요약

월말 정산 과정에서 자료 분산, 수작업 분류, 자료 취합 지연으로 인해 마감 지연과 업무 비효율이 반복적으로 발생하고 있음을 확인했습니다.

# STEP 1. 성과 문제 확정

## 성과 문제 문장

현재 월말 정산 자료 작성 업무에서는 자료 분산과 수작업 취합·분류 과정으로 인해 정산표 초안 작성 시간이 기대 수준인 1영업일 이내에서 실제 2~3영업일로 늘어나고 있으며, 그 결과 재작업과 보고 지연이 발생하고 있습니다.

## 기대 성과

- 월말 마감 후 1영업일 이내에 정산표 초안 완성
- 세금계산서와 지출 증빙 자료가 누락 없이 취합
- 거래처별·항목별 분류가 일정한 기준에 맞게 정리
- 관리자 또는 세무대리인에게 전달 가능한 수준의 초안 준비

## 실제 성과

- 자료가 이메일, 구글드라이브 등에 분산
- 부서별 제출 방식이 달라 취합에 시간이 많이 소요
- 누락 증빙은 이메일로 개별 재요청
- 거래처별·항목별 분류는 엑셀로 수작업 처리
- 정산표 초안 작성까지 2~3영업일 소요

## 성과 격차

- 정산표 초안 작성 시간이 1영업일 → 2~3영업일로 증가
- 자료 누락과 분류 오류로 수정 및 재작업 반복

## 조직 영향

- 월말 정산 마감 지연
- 관리자 보고 지연
- 세무대리인 전달 자료 준비 지연
- 회계담당자 업무 과부하
- 비용 확인 및 예산 관리 등 후속 의사결정 지연 가능성

## 우선순위 평가

| 기준 | 점수 | 판단 근거 |
|---|---:|---|
| Impact | 5/5 | 마감 지연, 보고 지연, 업무 과부하 발생 |
| Frequency/Persistence | 5/5 | 매월 월말마다 반복되는 구조적 문제 |
| Controllability | 4/5 | 제출 방식, 제출 기한, 분류 기준 등은 내부 개선 가능 |

# STEP 2. 업무 흐름 분석 및 병목 도출

## 업무 흐름 범위

각 부서가 세금계산서와 지출 증빙 자료를 제출하는 시점부터, 회계담당자가 월말 정산표 초안을 완성해 관리자 또는 세무대리인에게 검토 요청할 수 있는 상태로 정리하는 시점까지를 범위로 설정했습니다.

최종 회계 처리와 세무 신고는 이번 PoC 범위에서 제외했습니다.

## 현행 업무 흐름

1. 월말이 되면 각 부서에 세금계산서와 지출 증빙 자료 제출 요청
2. 각 부서 담당자가 이메일, 구글드라이브 등으로 증빙 자료 제출
3. 회계담당자가 이메일, 구글드라이브에 흩어진 자료 확인 및 취합
4. 제출된 자료와 카드 사용 내역 대조
5. 누락된 세금계산서나 영수증 확인
6. 누락 증빙이 있으면 각 부서 담당자에게 이메일로 재요청
7. 추가로 받은 자료 재확인 및 정리
8. 거래처별, 비용 항목별 지출 내역 분류
9. 엑셀에 월말 정산표 초안 작성
10. 정산표 초안을 관리자 또는 세무대리인에게 검토 요청 가능한 상태로 정리

## 확정 병목

### 1순위: 자료 취합

이메일과 구글드라이브에 분산된 자료를 찾고 모으는 데 탐색 시간이 많이 발생합니다.

### 2순위: 거래처/항목 분류

거래처명과 비용 항목 기준이 일정하지 않아 엑셀 수작업 시간이 많이 소요됩니다.

# STEP 3. AI 적용 적합성 판단 및 역할 분담

## AI 적용 판단 기준

STEP 2에서 도출한 핵심 병목인 다음 2개 단계를 대상으로 AI 적용 적합성을 판단했습니다.

1. 자료 취합
2. 거래처/항목 분류

---

## 1. 자료 취합 단계

### 지식 유형

형식지 중심

### 판단 근거

세금계산서, 영수증, 카드 사용 내역처럼 문서나 데이터로 남아 있는 자료를 기준으로 확인하는 업무입니다.

파일명, 거래일자, 거래처명, 금액, 증빙 종류, 제출 여부처럼 구조화 가능한 정보가 많습니다.

### 오류 비용

높음

### 판단 근거

초안 단계에서는 수정 가능하지만, 누락된 증빙이나 잘못 취합된 자료가 그대로 정산표에 반영되면 재무 자료 정확도와 세무대리인 전달 자료에 영향을 줄 수 있습니다.

### 2×2 분류

Quality control

### AI 역할

- 업로드된 증빙/지출 데이터 기반 취합 목록 생성
- 파일명, 날짜, 금액, 거래처 기준으로 1차 정리
- 카드 내역 대비 누락 의심 항목 리스트 생성

### 사람 역할

- 누락 여부 최종 판단 및 승인
- 예외 케이스 처리
- 정산표 반영 여부 결정

---

## 2. 거래처/항목 분류 단계

### 지식 유형

형식지 중심, 단 일부 판단 필요

### 판단 근거

거래처명, 사용일자, 금액, 카드 사용 내역, 기존 분류 기준, 계정과목 기준처럼 참고할 수 있는 데이터와 규칙이 있습니다.

반복 거래처나 자주 발생하는 비용 항목은 과거 이력을 기준으로 패턴화할 수 있습니다.

다만 같은 거래처라도 사용 목적에 따라 항목이 달라질 수 있고, 애매한 비용 항목은 회계담당자의 판단이 필요합니다.

### 오류 비용

높음

### 판단 근거

잘못된 거래처나 비용 항목으로 분류된 내용이 그대로 확정되면 재무 자료가 왜곡되고, 비용 처리, 예산 관리, 세무 검토에 영향을 줄 수 있습니다.

### 2×2 분류

Quality control

### AI 역할

- 거래처/항목 분류 초안 자동 제안
- 과거 분류 패턴 기반 추천
- 검토 필요 항목 표시

### 사람 역할

- 거래처/항목 최종 확정
- 계정과목 최종 판단
- 애매한 비용 항목 검토
- 예외 케이스 처리

---

## 최종 역할 분담

### AI가 하는 일

- 업로드된 증빙/지출 데이터 기반 취합 목록 생성
- 파일/데이터에서 거래일자, 금액, 거래처 등 구조화
- 카드 내역 대비 누락 의심 항목 리스트 생성
- 거래처/항목 분류 초안 자동 제안

### 사람이 반드시 하는 일

- 누락 여부 최종 판단 및 승인
- 거래처/항목 및 계정과목 최종 확정
- 예외 케이스 처리 및 회계 판단
- 정산표 반영 여부 결정

### Human-in-the-loop

- AI 취합 결과와 누락 의심 리스트 검토
- AI 분류 초안 검토 및 수정
- 최종 확정 전 승인

### AI 금지사항

- 검토 없이 정산표에 자동 반영하지 않음
- 누락 여부를 최종 확정하지 않음
- 계정과목/비용 처리에 대한 최종 판단을 내리지 않음
- 불확실한 데이터를 임의로 보정하거나 확정하지 않음

# STEP 4. PoC 설계 및 프로토타입 구상

## PoC 목적

AI가 업로드된 지출 내역과 증빙 자료 목록을 바탕으로 취합 목록, 누락 의심 항목, 거래처별·항목별 분류 초안을 생성했을 때 월말 정산표 초안 작성 시간을 줄일 수 있는지 검증합니다.

## 가설

AI가 취합 목록, 누락 의심 항목, 분류 초안을 생성하면 회계담당자의 수작업 취합·분류 시간이 줄어들고, 월말 정산표 초안 작성 시간이 기존 2~3영업일에서 1영업일 이내로 단축될 것입니다.

## MVP 범위

1. 엑셀/CSV 업로드
2. 거래일자, 거래처명, 금액, 사용 부서, 증빙 제출 여부 등 기본 항목 인식
3. 카드 사용 내역 대비 누락 의심 항목 표시
4. 거래처별·비용 항목별 분류 초안 생성
5. 회계담당자가 검토할 수 있는 정산표 초안 형태로 출력

## 제외 범위

1. 이메일, 구글드라이브, ERP와의 실시간 연동
2. 실제 세금계산서 원본 자동 수집
3. 최종 계정과목 확정
4. 세무 신고 또는 회계 처리 자동화
5. AI 결과를 검토 없이 정산표에 자동 반영하는 것

## 핵심 지표

1. 정산표 초안 작성 소요 시간
2. AI 초안 수정 건수 또는 수정 비율
3. 누락 의심 항목 탐지 정확도

## 성공 기준

1. 정산표 초안 작성 시간이 기존 2~3영업일에서 1영업일 이내로 단축됨
2. AI 초안 수정 비율이 30% 이하임
3. 누락 의심 항목의 실제 적중률이 70% 이상임

## 중단/전환 기준

1. AI를 사용해도 정산표 초안 작성 시간이 2영업일 이상 소요됨
2. AI 초안 수정 비율이 50% 이상임
3. 누락 의심 항목의 실제 적중률이 50% 미만임
4. AI가 근거 없이 계정과목이나 비용 항목을 확정적으로 제안함
5. 민감정보 처리나 보안 이슈가 발생할 가능성이 큼

## 웹앱 프로토타입 설계

### 화면 구성

- 파일 업로드 화면
- 데이터 미리보기 화면
- AI 분석 결과 화면
  - 취합 목록
  - 누락 의심 항목
  - 분류 제안
- 사용자 검토/수정 화면
- 최종 정산표 출력 화면

### 사용자 흐름

파일 업로드 → AI 분석 → 결과 확인 → 사람이 수정 → 최종 정산표 확정

### 수집 데이터/로그

- 처리 시간
- 사용자 수정 항목 수
- 수정 전/후 비교
- 누락 탐지 결과

# STEP 5. OKR 및 의사결정 기준

## Objective

AI 기반 취합·분류 초안 생성을 통해 월말 정산표 초안 작성 시간을 단축하고, 회계담당자의 수작업 부담을 줄이면서 검토 중심의 업무 방식으로 전환합니다.

## Key Results

1. 정산표 초안 작성 시간을 기존 2~3영업일에서 1영업일 이내로 단축한다.
2. AI가 생성한 취합 목록 및 거래처·비용 항목 분류 초안 중 회계담당자가 수정해야 하는 비율을 30% 이하로 유지한다.
3. AI가 표시한 누락 의심 항목 중 실제 누락으로 확인되는 비율을 70% 이상으로 유지한다.
4. 회계담당자가 AI 초안을 기반으로 업무를 수행했을 때 기존 수작업 대비 효율이 개선되었다고 평가한다.

## 운영 단위

- 월말 정산 프로세스 중 “정산표 초안 작성” 업무를 대상으로 한 PoC 과제 단위로 운영
- 초기: 단일 회계담당자 + 소규모 데이터
- 이후: 효과 검증 시 팀 단위 또는 조직 단위로 확산 검토

## 확산 / 유지 / 중단 기준

### 확산

KR 4개 중 3개 이상 달성 시  
→ 실무 적용 효과가 있다고 판단하고 팀 단위 또는 유사 업무로 확산

### 유지 및 개선

KR 4개 중 2개 달성 시  
→ 일부 효과는 확인된 것으로 보고 AI 역할 범위 또는 데이터 구조를 보완 후 재실험

### 중단 또는 축소

KR 4개 중 1개 이하 달성 시  
→ 실무 적용 효과가 낮다고 판단하고 AI 역할을 “취합 목록 생성 / 누락 의심 표시” 수준으로 축소하거나 방향 재검토

## 운영 시 수집 데이터

- 정산표 초안 작성 소요 시간
- AI 초안 대비 수정된 항목 수 및 수정 비율
- 누락 의심 항목 수 및 실제 누락 적중률
- 사용자 체감 효율 점수

## STEP 5 요약

AI 기반 정산 초안 자동화의 실효성을 검증하기 위해 시간 단축, 수정 비율, 누락 탐지 정확도, 사용자 체감 효율을 기준으로 OKR을 수립하고, 확산/유지/중단 의사결정 기준까지 정의했습니다.
